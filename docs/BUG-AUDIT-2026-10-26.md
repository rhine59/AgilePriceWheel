# Container and iOS bug audit — 26 October 2026

## Confirmed and corrected

| Finding | Trigger and previous result | Correction / regression coverage |
| --- | --- | --- |
| Missing price displayed as OFF | A fresh HTTP response with stale/missing prices produced a green policy OFF | Price state is optional; unavailable stays neutral, valid OFF stays green. Swift regression covers stale/missing/valid prices |
| Extra week for midnight OFF | OFF exactly at Monday 00:00 appeared in the next week despite no elapsed overlap | Session end is exclusive at the weekly boundary |
| Unknown end repeated indefinitely | An old ON without confirmed OFF appeared in later weeks without evidence | Keep it in its starting week; carry it into a later week only with recorded confirmed rate/activity there |
| Retention depended on writes | After a long idle period an expired action could remain visible in the oldest calendar week | Apply the 366-day cutoff to action reads as well as sessions; disk cleanup still occurs on append |
| Session truncation not disclosed | More than 2,000 overlapping sessions with few/no in-week actions were silently capped | Cap both collections and set truncated if either exceeds the limit |
| Mixed read snapshots | A writer could commit between queries for actions and rates | Explicit read transaction makes the response consistent; concurrent-writer regression proves isolation |

The first three backend edge cases failed against the deployed baseline before
correction. The price display bug was confirmed in the SwiftUI expression and
covered by a new focused model check. The two robustness cases have dedicated
regression tests. No boost payloads, price thresholds or control timing changed.

## Verification and operational limits

178 backend tests, 62 narrated offline checks and 15 focused iOS checks passed.
The signed app built and was installed in place. The idle container was upgraded
with a retained rollback image and history backup; saved policy, enabled switch,
mounts and old records were checked. Public HTTPS verification checks history,
status, freshness and unchanged 7p/8p prices. No forced heating test was performed.

The live baseline had zero restarts, fresh pricing, healthy HTTP, no control or
history errors and heating disabled while prices were above policy. These checks
are a bounded review, not proof that all bugs are absent. Session costs remain
configured-load estimates; old records without saved load/rates legitimately
have no estimate. Cloud outages can delay heating shutdown, and an uninterrupted
post-latency-fix real cycle has not yet been observed. Android heating parity is
still required and not implemented/tested by this iOS/container audit.

The earlier named checkpoint tag is preserved. This audit is a later change, not
a rewrite of the saved checkpoint. Rebuild and service details remain in the
Homely repository's controller/REBUILD.md and controller/SERVICES.md.

The complete iOS unit target also passed (14 heating model checks and one empty
placeholder). The placeholder supplies no meaningful assurance for non-heating
pricing/solar screens; broader native app coverage remains a gap. The separate
heating navigation UI check passed. No Android heating code was reviewed because
that feature is not implemented yet.
